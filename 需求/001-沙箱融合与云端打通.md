# 需求1：沙箱融合与云端打通（本地 NsJail + 云端 llm-sandbox）

**状态**：进行中  
**优先级**：高  
**创建日期**：2025-03-11

---

## 背景 / 问题

- 当前项目有 text2sql 系统，需要 llm-sandbox 的 Docker 沙箱能力。
- 已有京东云服务器，希望沙箱多租户部署在云端，提供接口供本项目调用。
- 沙箱需同步本项目数据库副本，交互模式为：本项目调用接口 → 沙箱返回结果。
- 本地环境需运行 NsJail 沙箱，并与云端 llm-sandbox 打通，使沙箱能正常融合到系统中。

## 目标与范围

### 目标

- **统一沙箱能力入口**：text2sql（及后续执行型能力）可以通过同一套“沙箱执行接口”选择本地 NsJail 或云端 llm-sandbox。
- **安全可控**：云端只提供必要的执行能力，具备鉴权、隔离、限流与审计；严格禁止任何危险/破坏性操作。
- **数据可用**：沙箱侧持有业务数据库的**可查询副本**，满足 text2sql 的查询/验证需求，并可按策略更新。

### 范围内

- 云端部署 llm-sandbox（多租户）、对外提供 HTTP/API、可观测（健康检查、日志、指标基础）。
- 数据库副本同步到沙箱侧并可被执行环境使用（以只读为主，必要时可控更新）。
- 本地 NsJail 可运行，并与云端形成可配置的路由/分流策略（统一调用路径或可切换）。
- 端到端联调：本项目 →（本地或云端）沙箱 → 返回结果 → 进入 text2sql 流程闭环。

### 范围外（本需求不做或不保证）

- 不改造/迁移线上生产数据库（只做副本/快照/导出导入）。
- 不提供通用“任意代码执行”能力（仅允许白名单动作，如 SQL 查询、指定目录读写、受限资源执行）。
- 不涉及云服务器上其他业务服务的停用/卸载/迁移。

## 需求描述

1. **云端**：在京东云上部署 llm-sandbox 多租户 Docker 沙箱，对外提供 HTTP/API，不对云服务器做任何危险操作（不删目录、不执行危险命令）。
2. **数据库同步**：沙箱侧持有本项目数据库的副本，由本项目或定时任务同步到沙箱可用路径（只读或可控更新）。
3. **调用关系**：本项目通过调用沙箱接口发起执行请求，沙箱在副本上执行后返回结果。
4. **本地**：本地运行 NsJail 沙箱，与云端 llm-sandbox 打通（统一入口或分流策略），使 text2sql 等流程可选用本地/云端沙箱。
5. **验收**：沙箱能正常融合到系统中，端到端运行正常（含 DB 同步与接口调用）。

## 执行策略

- **轻量级任务**：使用 **NsJail** 沙箱（本地、低开销、快速）。
- **长时间任务**：使用 **llm-sandbox** 沙箱（云端或本地 Docker，适合耗时、资源占用较高的执行）。

## 总体架构（逻辑视图）

- **调用方（本项目）**
  - 生成执行请求（tenant_id / project_id、task_type、payload、超时、资源配额）。
  - 按路由策略选择执行端：本地 NsJail 或云端 llm-sandbox。
- **本地 NsJail 执行器**
  - 适合短时、低资源、低延迟任务（例如：SQL 语法检查、轻量查询、规则验证等）。
- **云端 llm-sandbox 服务（多租户）**
  - 暴露 HTTP/API：提交任务、查询结果、健康检查。
  - 在受限容器内执行白名单动作，读写受控目录，访问只读数据库副本（或仅允许本地 socket/网络到副本）。
- **数据库副本同步**
  - 由“同步作业（本项目或定时任务）”将副本更新到云端沙箱可访问位置，并确保可回滚。

## 接口契约（建议）

> 说明：以下为建议契约，用于“统一入口与可落地联调”。实际路径/字段可按现有工程风格调整，但需要固定并版本化。

### 1）健康检查

- `GET /healthz`
  - **200**：服务可用（返回 build/version、依赖检查简要信息）

### 2）提交执行任务（统一入口）

- `POST /api/v1/execute`
  - **请求头**
    - `Authorization: Bearer <token>`（或等价签名方案，见“安全”）
    - `X-Tenant-Id: <tenant_id>`
    - `X-Request-Id: <uuid>`（便于追踪）
  - **请求体（示例）**
    - `task_type`: `sql_readonly` / `python_sandbox`（若允许）/ `shell_whitelist`（若允许）
    - `timeout_ms`
    - `payload`
  - **响应**
    - `job_id`
    - `status`: `queued|running|succeeded|failed`

### 3）查询执行结果

- `GET /api/v1/jobs/{job_id}`
  - **响应**
    - `status`
    - `stdout` / `stderr`（可截断）
    - `result`（结构化结果，特别是 SQL 返回）
    - `metrics`（耗时、资源用量摘要）

### 4）数据库副本同步/刷新（可选，若由本项目触发）

- `POST /api/v1/db/sync`
  - **用途**：触发云端拉取/切换到新的数据库副本（建议“切换指针”方式，保证原子性与可回滚）
  - **响应**：`sync_id`、`status`

## 云服务器使用规则

- **仅用于部署沙箱 llm-sandbox 相关**：只做与 llm-sandbox 沙箱部署、运行、维护有关的操作。
- **不得影响其他软件**：不能停用、卸载、覆盖或修改云服务器上已有其他软件与服务。
- **禁止危险操作**：禁止删除目录、批量删文件、格式化磁盘、修改系统关键配置、关闭/占用其他服务端口等任何可能影响整机稳定与现有业务的操作。

## 约束规则

- 不能对云服务器进行任何危险操作：禁止删除目录、批量删文件、格式化、修改系统关键配置等。
- 本地必须能运行 NsJail 沙箱。
- 本地 NsJail 与云端 llm-sandbox 需打通（统一调用路径或可配置切换）。

## 数据库副本同步方案（落地建议）

### 原则

- **只读优先**：沙箱任务默认只允许读库（避免任何数据破坏与一致性风险）。
- **可回滚**：每次同步形成版本（timestamp 或递增版本号），云端执行侧通过“当前指针”切换到新版本。
- **最小权限**：同步账号仅具备导出/读取所需权限；云端运行用户对副本目录最小读权限。

### 同步方式（任选其一，优先从易落地开始）

- **方式 A：定时导出 + 上传 + 原子切换**
  - 本项目侧定时 `dump`（或导出为快照文件）→ 上传到云端指定目录（新版本目录）→ 校验（大小/校验和）→ 触发切换指针。
- **方式 B：云端拉取（受控）**
  - 云端定时从受控源拉取最新副本（需要严格的源地址白名单与认证）。

### 切换策略

- 新副本导入完成后，更新 `current` 软链接（或配置中的版本号）实现**原子切换**。
- 切换失败或新副本不可用时，回滚到上一版本并记录告警。

## 本地 NsJail 与云端 llm-sandbox 打通（策略）

### 统一入口

- 在本项目内抽象 `SandboxExecutor`（或等价模块），提供统一方法（例如 `execute(task)`），内部根据配置路由：
  - `SANDBOX_MODE=local`：强制 NsJail
  - `SANDBOX_MODE=cloud`：强制云端
  - `SANDBOX_MODE=auto`：按规则分流（任务类型/预计耗时/资源需求）

### 分流建议（默认）

- SQL 只读、短超时、低资源：优先本地 NsJail（更低延迟）。
- 需要容器依赖/长时间/高资源：走云端 llm-sandbox（隔离更强、资源更弹性）。
- 云端不可用时：自动降级到本地（仅对可降级任务），并返回“降级标记”便于追踪。

## 安全与合规（必须项）

- **鉴权**：云端 API 必须鉴权（Bearer Token 或 HMAC 签名），并与 `tenant_id` 绑定权限。
- **限流**：按 `tenant_id` 与 IP 维度限流（防止滥用与意外压垮主机）。
- **白名单执行**：仅允许预定义 `task_type`；对于 SQL 强制只读（禁止 DDL/DML/多语句等，必要时在执行前做解析/校验）。
- **资源隔离**：容器/沙箱限制 CPU、内存、磁盘、网络访问（只允许到副本/必要依赖）。
- **审计**：记录 `request_id`、`tenant_id`、任务摘要、执行耗时、结果状态；敏感字段脱敏。

## 交付物与里程碑（建议拆分）

- **交付物**
  - 云端 llm-sandbox 可运行实例（多租户、鉴权、健康检查、执行/查询接口）
  - DB 副本同步作业（生成版本、上传/拉取、校验、原子切换、回滚）
  - 本项目侧统一 `SandboxExecutor`（或等价模块）与路由配置（local/cloud/auto）
  - 最小审计日志与联调说明（请求字段、错误码/失败场景）
- **里程碑（示例）**
  - M1：云端服务拉起 + `/healthz` 可用
  - M2：`/execute` 与 `/jobs/{id}` 可跑通（先用假数据/简单任务）
  - M3：DB 副本同步与切换可用（含回滚）
  - M4：本地 NsJail 与云端分流打通（auto 策略生效）
  - M5：text2sql 端到端验收通过

## 失败处理与回滚

- **云端不可用**：对可降级任务自动走本地 NsJail；不可降级任务明确返回可识别错误码与提示。
- **DB 副本异常**：保持使用上一版本 `current`；记录告警并阻断切换。
- **接口超时/任务失败**：返回可追踪的 `request_id/job_id`，保留失败上下文（脱敏）便于复盘。

## 验收标准

- [ ] 云端 llm-sandbox 服务可部署并对外提供安全接口（无危险操作）。
- [ ] 本项目数据库副本能同步到沙箱侧并可被沙箱只读/安全使用。
- [ ] 本项目通过接口调用沙箱并正确拿到执行结果。
- [ ] 本地 NsJail 沙箱可独立运行且与云端打通（统一或可切换）。
- [ ] 沙箱完整融合到 text2sql 系统，端到端运行正常。
- [ ] 云端接口具备鉴权与基本限流；具备最小审计日志（含 request_id/tenant_id/状态/耗时）。
- [ ] 数据库副本切换可回滚（至少保留最近 2 个版本），并有失败告警/错误可追踪信息。

## 备注

- 多租户：同一套沙箱服务可被多个项目/租户调用，通过 tenant_id 或 project_id 区分。
- 安全：云端接口需鉴权、限流；沙箱内仅允许执行白名单操作（如只读 SQL、指定目录读写）。
