## 六、专项：grep 结束到「决策与观察」打字的空窗优化（新增）

### 6.1 现状与根因（已定位）

| 现象 | 当前行为 | 根因 |
|------|----------|------|
| grep 执行结果已出现，但「决策与观察」约 8~15s 后才开始打字 | 后端先做 observe 分析（含 XML/结构化解析），完成后才发 `react_ui_stream(decision_observe)` | `decision_observe` 与 `ui_observe_summary` 位于 observe 分析之后，且前端对 `reasoning_step(segment=observe)` 默认不展示 |
| 用户体感“卡住” | 执行区已完成，决策区无增量文本 | 观察分析正在进行，但缺少可见进度信号与可读流 |

### 6.2 目标（P0/P1）

| 目标 | 优先级 | 指标（建议） |
|------|--------|--------------|
| 去除“静默空窗”体感 | P0 | grep 结束后 `<= 800ms` 内，决策区出现可见动态（文案或进度） |
| 决策区首字时间显著缩短 | P0 | P95 首字时间较现状下降 50% 以上 |
| 总时延不明显回升 | P1 | 端到端完成时长变化 `<= +5%` |

### 6.3 方案设计（先体验，后性能）

1. **方案 A（P0，低风险，先落地）：可见化 observe 进行中**
   - 后端：在 `observation` 后立刻发一条 `react_ui_stream(channel=decision_observe)` 引导文案（如“正在分析 grep 结果并生成下一步建议…”）。
   - 前端：`showDecisionBlock` 在收到该引导文案后立即显示决策面板（即使 `llmDraft` 仅为引导句）。
   - 保留现有串行流程，不改分析链路，只改“何时让用户看到变化”。

2. **方案 B（P1，中风险，提首字时间）：并行化用户文案流**
   - 后端：`_stream_agent_observe_with_narrative` 执行时，增加并行任务提前产出 `ui_observe_summary`（或先发摘要骨架再补充）。
   - 结构化解析仍保留，作为后续上下文更新依据；用户文案不再完全依赖其完成。
   - 需要处理并行任务取消、异常兜底、重复文案去重。

3. **方案 C（P1，高收益，需谨慎）：前端显示 observe reasoning 片段**
   - 前端允许展示 `reasoning_step(segment=observe)` 到“决策与观察”的临时子区（例如“分析过程”）。
   - 待 `react_ui_stream(decision_observe)` 到达后，可折叠或替换临时内容。
   - 风险：可能泄露中间推理风格，需控制措辞与长度。

### 6.4 推荐实施顺序

| 阶段 | 选择 | 预期收益 | 风险 |
|------|------|----------|------|
| 第 1 步（本周） | 先做方案 A | 立即消除“卡住感”，改动最小 | 几乎无逻辑风险 |
| 第 2 步（下周） | 灰度方案 B | 明显缩短“首字等待” | 并行一致性、重复输出 |
| 第 3 步（可选） | 评估方案 C | 进一步减少空白 | UI 与内容策略复杂 |

### 6.5 事件时序（目标态）

```text
tool:end(grep)
  -> observation
  -> react_ui_stream(decision_observe, "正在分析...")
  -> (并行) observe_narrative / parse_xml_findings
  -> react_ui_stream(decision_observe, 增量正文...)
  -> step_status done
```

### 6.6 验收与监控埋点

- 新增时延指标：
  - `t_tool_end`：grep 工具结束时间。
  - `t_decision_visible`：决策区首次可见时间。
  - `t_decision_first_char`：决策区首字到达时间。
  - `t_observe_done`：observe 结构化解析完成时间。
- 看板关注：
  - `decision_visible_delay = t_decision_visible - t_tool_end`
  - `decision_first_char_delay = t_decision_first_char - t_tool_end`
  - `observe_backend_cost = t_observe_done - t_tool_end`
- DoD（本专项）：
  1. 90% 会话在 grep 结束后 0.8s 内出现决策区动态。
  2. 不影响后续 context_update 的正确性。
  3. 失败回退时仍可看到“分析中/失败提示”，不出现无反馈静默。
