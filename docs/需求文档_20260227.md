# 需求文档 - 2026年2月27日

## 需求一：引入 Text2SQL 工具

### 背景
当前 modify 工具和 database 相关工具中，数据库操作代码为手写 SQL，存在以下问题：
- 维护成本高，每次表结构变更需同步修改多处代码
- 扩展性差，新增查询场景需编写新的查询逻辑
- 代码重复，相似的查询逻辑散落在多个工具中

### 目标
引入 Text2SQL 方案（LangChain + sqlglot），实现自然语言到 SQL 的自动转换，降低数据库操作维护成本。

### 技术方案

#### 1. 技术选型
- **LangChain**：提供 LLM 与数据库交互的链式调用能力
- **sqlglot**：SQL 解析与优化，支持多数据库方言，用于 SQL 校验和优化

#### 2. 核心模块设计

```
agents/tools/
├── text2sql_tool.py      # Text2SQL 核心工具
│   ├── schema_manager    # 数据库 Schema 管理
│   ├── sql_generator     # 自然语言转 SQL
│   ├── sql_validator     # SQL 校验（sqlglot）
│   └── sql_executor      # 安全执行 SQL
```

#### 3. 改造范围

| 工具 | 改造内容 |
|------|----------|
| `modify_tool.py` | 将手写数据库操作改为 Text2SQL 调用 |
| `database_tool.py` | 查询逻辑迁移至 Text2SQL |
| `grep_tool.py` | 保留现有逻辑（grep 定位不涉及复杂 SQL） |

#### 4. 接口设计

```python
class Text2SQLTool:
    """Text2SQL 工具"""
    
    def natural_language_to_sql(self, query: str, context: dict) -> str:
        """自然语言转 SQL"""
        pass
    
    def validate_sql(self, sql: str) -> bool:
        """SQL 校验，防止注入"""
        pass
    
    def execute_safe_sql(self, sql: str, params: dict) -> list:
        """安全执行 SQL（只读或受控写操作）"""
        pass
```

#### 5. 安全措施
- SQL 注入防护：sqlglot 解析校验，禁止危险操作（DROP、TRUNCATE 等）
- 权限控制：基于 project_id 的数据隔离
- 操作审计：记录所有 SQL 执行日志

### 验收标准
- [ ] Text2SQL 工具可独立运行
- [ ] modify 工具集成 Text2SQL，功能不变
- [ ] database 工具集成 Text2SQL，功能不变
- [ ] SQL 注入测试通过
- [ ] 性能不低于现有实现

## 需求二：Skill 动态加载机制

### 背景
当前 Agent 提示词中硬编码了工具组合逻辑，例如：
```
修改 Bug 流程：先使用 grep 定位，再使用 modify 修改
```

存在问题：
- 扩展性差，新增 skill 需修改提示词模板
- 维护成本高，skill 逻辑分散在多处
- 复用困难，相似场景无法共享 skill

### 目标
建立 Skill 动态加载机制，实现：
- Skill 配置化管理
- 动态加载与执行
- 便于后续扩展更多 Skill

### 技术方案

#### 1. Skill 定义规范

每个 Skill 为独立的 YAML/JSON 配置文件：

```yaml
# skills/modify_bug.yaml
name: modify_bug
description: 修改 Bug 信息
trigger:
  intents: [修改, 更新, 编辑]
  entities: [bug, 缺陷]
tools:
  - name: grep
    purpose: 定位目标 Bug
    params:
      target: bug
      keywords: ${user_keywords}
  - name: modify
    purpose: 执行修改操作
    params:
      target: bug
      target_id: ${grep_result.first_bug_id}
      modifications: ${user_modifications}
workflow:
  - step: 1
    tool: grep
    description: 定位目标 Bug
  - step: 2
    tool: modify
    description: 执行修改
    depends_on: step_1
```

#### 2. 目录结构

```
.qoder/skills/
├── modify_bug.yaml         # 修改 Bug
├── modify_badcase.yaml     # 修改 BadCase
├── modify_testcase.yaml    # 修改测试用例
├── create_bug.yaml         # 创建 Bug
├── create_badcase.yaml     # 创建 BadCase
└── query_bugs.yaml         # 查询 Bug 列表
```

## 需求三：完善测试 Agent - 引入 OpenClaw 沙箱

### 背景
当前测试 Agent 服务运行在远端服务器，但浏览器操作需要在用户本地执行，存在以下问题：
- 浏览器环境不一致，远端无法准确模拟用户本地行为
- 网络延迟影响测试效率
- 用户本地浏览器配置无法复用

### 目标
引入 OpenClaw 沙箱机制，实现：
- 服务端运行 Agent 逻辑
- 客户端浏览器操作在用户本地执行
- 通过沙箱建立安全通信通道

│ - 浏览器控制     │      │ - 逻辑处理      │

## 需求五：开发 Java & Python SDK

### 背景
需要采集 BadCase 对话中的问题因素，用于分析和改进。

### 目标
开发 Java 和 Python 版本 SDK，采集导致对话效果不佳的 5 种因素。

### 5 种问题因素定义
1. **响应延迟**：LLM 响应时间过长
2. **内容不准确**：回答与问题不符
3. **逻辑混乱**：回答结构不清晰
4. **信息缺失**：关键信息未提供
5. **格式错误**：输出格式不符合要求

### 技术方案

#### Java 版本（基于 Micrometer）
```java
// java-sdk/src/main/java/com/badcase/collector/BadCaseCollector.java
public class BadCaseCollector {
    private MeterRegistry registry;
    
    public BadCaseCollector(MeterRegistry registry) {
        this.registry = registry;
    }
    
    public void recordResponseDelay(String sessionId, Duration delay) {
        Timer.builder("badcase.response.delay")
            .tag("session_id", sessionId)
            .register(registry)
            .record(delay);
    }
    
    public void recordInaccuracy(String sessionId, String category) {
        Counter.builder("badcase.inaccuracy")
            .tag("category", category)
            .tag("session_id", sessionId)
            .register(registry)
            .increment();
    }
    
    // 其他 3 种因素类似...
}
```

#### Python 版本（类似实现）
```python
# python-sdk/badcase_collector.py
import time
from prometheus_client import Counter, Histogram

class BadCaseCollector:
    def __init__(self, registry=None):
        self.response_delay = Histogram(
            'badcase_response_delay_seconds',
            'Response delay time',
            ['session_id']
        )
        self.inaccuracy_counter = Counter(
            'badcase_inaccuracy_total',
            'Inaccuracy count',
            ['category', 'session_id']
        )
        # 其他指标...
    
    def record_response_delay(self, session_id: str, delay: float):
        self.response_delay.labels(session_id=session_id).observe(delay)
    
    def record_inaccuracy(self, session_id: str, category: str):
        self.inaccuracy_counter.labels(
            category=category, 
            session_id=session_id
        ).inc()
```

### 集成示例
```python
# 使用示例

# 记录响应延迟
start_time = time.time()
# ... LLM 处理 ...
delay = time.time() - start_time
collector.record_response_delay(session_id="sess_123", delay=delay)

# 记录不准确
if not is_accurate(response):
    collector.record_inaccuracy(session_id="sess_123", category="content")
```
