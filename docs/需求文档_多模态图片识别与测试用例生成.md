# 需求文档 - 多模态图片识别与测试用例生成

## 1. 概述

### 1.1 背景

参考 Cursor 的多模态交互方式（上传图片、语音录入），为 BadCase Doctor 增加图片输入能力。用户可在对话中上传图片，由视觉模型理解图片内容、生成文本描述，再结合用户选定的业务模型（如 GLM、文心等）完成具体意图处理。

**核心思路**：将「看图」与「做任务」分离——视觉模型只负责「读懂图片」，业务模型根据「图片描述 + 用户意图」执行任务。这样既充分利用各模型优势，又避免要求所有模型都支持多模态。

### 1.2 目标

1. **支持图片上传**：对话面板支持上传图片，交互方式类似 Cursor
2. **双模型协作**：
   - **视觉模型**（如 Qwen2-VL、qwen-3.5-plus 等支持图像的模型）：根据对话意图，描述图片内容
   - **业务模型**（用户在对话面板选择的模型）：基于图片描述 + 用户文本，处理具体意图
3. **MVP 场景**：优先实现「原型图 → 测试用例」——上传 UI 原型图，自动生成测试用例

## 3. 架构设计

### 3.1 整体流程

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         前端（对话面板）                                   │
│  ┌──────────────────────────────────────────────────────────────────┐   │
│  │  [文本输入] [📷 上传图片] [模型选择: GLM-5 / 文心 / Qwen...] [发送] │   │
│  └──────────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                          后端 API                                        │
│  请求体: { content, images: [base64...], model, session_id }             │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
              ┌─────────────────────┼─────────────────────┐
              ▼                     ▼                     ▼
┌─────────────────────┐  ┌─────────────────────┐  ┌─────────────────────┐
│ 有图片？             │  │ 无图片              │  │ 有图片               │
│ → 视觉模型           │  │ → 直接走现有流程    │  │ → 视觉模型描述图片    │
│   (Qwen2-VL /       │  │   (Agent / Chat)    │  │ → 将描述注入上下文    │
│    qwen3.5-plus)    │  │                     │  │ → 业务模型处理意图    │
└─────────────────────┘  └─────────────────────┘  └─────────────────────┘
```

### 3.2 双模型协作逻辑

| 阶段 | 模型 | 职责 |
|------|------|------|
| 1. 图片理解 | 视觉模型（固定） | 根据用户意图 + 图片，输出结构化描述 |
| 2. 任务执行 | 业务模型（用户选择） | 根据「图片描述 + 用户文本」完成 Agent/Chat 任务 |

**示例（原型图 → 测试用例）**：

1. 用户上传原型图 + 文本：「根据这张原型图生成测试用例」
2. 视觉模型输出：`该图片为登录页面原型，包含：用户名输入框、密码输入框、登录按钮、忘记密码链接...`
3. 业务模型收到：`[图片描述] 该图片为登录页面原型... [用户] 根据这张原型图生成测试用例`
4. 业务模型调用 grep/create 等工具，生成测试用例并写入项目

## 4. 技术方案

### 4.1 视觉模型选型

| 模型 | 说明 | 推荐场景 |
|------|------|----------|
| **qwen3.5-plus** | 阿里云 DashScope，支持图像输入 | 首选，与现有 Qwen 配置一致 |
| **Qwen2-VL** | 通义千问视觉语言模型 | 备选，图像理解能力强 |
| **GLM-4V / glm-4.6v** | 智谱视觉模型 | 项目中 browser_test 已用，可复用 |

**建议**：默认使用 `qwen3.5-plus`（若确认支持图像）或 `qwen2-vl-max`，通过配置可切换。

### 4.3 图片描述服务

```python
# agents/vision_describe.py
class VisionDescribeService:
    """图片描述服务：根据对话意图，调用视觉模型生成图片描述"""

    def __init__(self, vision_model: str = "qwen3.5-plus"):
        self.llm = get_vision_llm(vision_model)

    def describe_image(
        self,
        image_base64: str,
        user_intent: str,
        context: str = ""
    ) -> str:
        """
        根据用户意图描述图片。
        - user_intent: 用户输入的文本，用于引导描述侧重点
        - context: 可选，如「当前项目为 XX，请重点描述与测试相关的元素」
        """
        prompt = self._build_prompt(user_intent, context)
        return self._call_vision(image_base64, prompt)

    def describe_prototype_for_testcase(self, image_base64: str, user_intent: str) -> str:
        """专门用于「原型图 → 测试用例」场景，输出结构化描述"""
        prompt = """
        这是一张 UI 原型图。请详细描述：
        1. 页面类型（登录、列表、表单等）
        2. 所有可交互元素（按钮、输入框、链接、下拉框等）及其位置/层级
        3. 业务含义（如有标签、提示文案）
        4. 可能的操作流程
        输出格式尽量结构化，便于后续生成测试用例。
        """
        return self._call_vision(image_base64, prompt + f"\n用户补充说明：{user_intent}")
```

#### 4.4.2 处理流程（伪代码）

```python
# routers/chat.py 或 agent.py
def handle_chat_request(data):
    content = data.get("content", "")
    images = data.get("images", [])
    model = data.get("model", "qwen3.5-plus")

    if images:
        # 1. 调用视觉模型生成图片描述
        vision_svc = VisionDescribeService()
        descriptions = []
        for img in images:
            desc = vision_svc.describe_prototype_for_testcase(
                img["data"], content
            )
            descriptions.append(desc)
        # 2. 将描述注入到用户消息
        enriched_content = "[图片描述]\n" + "\n\n".join(descriptions) + "\n\n[用户] " + content
        content = enriched_content
        # 3. 后续用业务模型处理（Agent 或 Chat）
        # ...

    # 按现有逻辑调用 Agent / Chat
    return process_with_model(content, model, ...)
```

## 5. MVP：原型图 → 测试用例

### 5.1 场景说明

用户上传一张 UI 原型图（如 Axure/Figma 导出的截图），输入「根据这张原型图生成测试用例」，系统应：

1. 视觉模型识别原型图中的元素（按钮、输入框、链接、表单等）
2. 生成结构化描述
3. 业务模型根据描述 + 项目上下文，调用 `create` 工具生成测试用例并写入项目

### 5.2 提示词设计（视觉模型）

```
你是一个 UI 原型图分析助手。用户上传了一张原型图，需要根据它生成测试用例。

请按以下结构描述图片内容：
1. **页面类型**：如登录页、列表页、表单页等
2. **可交互元素**：
   - 类型（按钮/输入框/链接/下拉/单选/多选等）
   - 位置/顺序
   - 文案或占位符
3. **业务流程**：用户可能进行的操作路径
4. **注意事项**：如必填项、校验规则等（如有）

输出要求：清晰、结构化，便于后续模型生成测试用例。用户补充说明：{user_intent}
```

### 5.3 与现有能力的关系

| 现有能力 | 关系 |
|----------|------|
| Agent + create 工具 | 业务模型根据图片描述调用 create，创建测试用例 |
| Skill 机制 | 可新增 `create_testcase_from_prototype` skill，匹配「原型图+生成测试用例」意图 |
| 项目/测试用例管理 | 生成的测试用例写入当前项目的测试用例列表 |

## 7. 非功能需求

| 项目 | 要求 |
|------|------|
| 图片大小 | 单张建议 ≤ 4MB，超出时前端压缩或后端拒绝 |
| 图片数量 | 单次请求建议 ≤ 5 张 |
| 视觉模型超时 | 建议 30s，失败时返回明确错误 |
| 存储 | 图片不落库，仅当次请求使用；历史消息可存图片 URL 或 base64（按现有消息存储策略） |
