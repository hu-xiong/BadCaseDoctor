# modify 步骤耗时分析（需求文档）

## 1. 背景与目标

在对话 Agent 中执行「修改测试用例负责人」等操作时，界面上 **modify 单步** 可出现约 **20s 级**耗时。本文档将 **modify 从用户发话到沙箱预览就绪** 拆解为可观测阶段，并记录**已落地的优化**与**配置口径**。

**目标：**

- 统一「这一步 Xs」究竟包含哪些子步骤。
- 标出热点与环境变量；批量场景下的体验（流式、批量读、批量沙箱）。
- 为后续 Profiling（分段耗时等）留扩展位。

---

## 2. 耗时口径（界面「步骤耗时」）

前端步骤上的 **「耗时 Xs」** 主要来自：

- 后端在下发步骤事件时携带的 `duration`（秒），或
- 前端用 **`stepStartedAt` 到收到该步 `observation` 的 wall time** 兜底。

该时间通常覆盖 **「本 ReAct 步内：模型产出 tool 调用 → 工具执行完毕 → 观测汇总」**；批量预览时中间会穿插多条 **`batch_preview_row`** 事件，**不阻塞**工具返回前的其他 SSE（仍由单步 `observation` 收口）。

---

## 3. 端到端阶段分解（当前实现摘要）

### 3.1 ReAct 外层

| 阶段 | 说明 |
|------|------|
| 门控 / THINK / grep | 与首轮规划、检索相关，可能占大头 |
| modifications 抽取 | 正则失败时可能再调 LLM |

### 3.2 modify 工具内（`agents/tools/modify_tool.py`）

- **定位**：默认 `MODIFY_LOOKUP_ORM_FIRST=1` 先 ORM 标题匹配，再 Text2SQL。
- **读行**：默认 `MODIFY_ORIGINAL_DATA_ORM_FIRST=1` 优先 ORM；批量预览使用 **`_fetch_original_rows_batch_orm`（一次 IN 查询）**。
- **沙箱**：`MODIFY_SANDBOX_DIRECT_SQL=1` 时直拼 UPDATE；批量为 **一次副本 + `executescript` 多条 UPDATE**。
- **批量预览流式**：`MODIFY_BATCH_PREVIEW_STREAM=1`（默认）时，**每生成一条 diff** 即通过 `progress_queue` 推送结构化事件（前缀 `__MODIFY_BATCH_ROW__`），经 `react_simplified` 转为 **`event: batch_preview_row`**，前端 **`batchPreviewRows` + 日志行** 实时累积。
- **快速落库（无沙箱预览）**：服务端需 **`MODIFY_ALLOW_FAST_APPLY=1`**，且调用方传入 **`skip_preview: true`**，且修改字段仅含 **状态 / 负责人**（映射后为 `assignee_id`+`status` 或 badcase 的 `assignee`+`status`）时，**直接走落库分支**；响应中带 `fast_apply`、`sandbox_skipped`。**不提供自动回滚**，依赖备份/运维策略。

### 3.3 Text2SQL schema 缓存（`agents/tools/sqlcoder_agent.py`）

- `generate_sql` 热路径使用 **`_get_schema_prompt_for_generate()`**：按 SQLite **文件 mtime** 作为缓存键，未变更则复用已格式化的 schema 文本；变更时重新 `_load_schema_info()`。
- 与既有 **SQL 结果缓存**（`TEXT2SQL_SQL_CACHE_TTL` / `TEXT2SQL_SQL_CACHE_MAX`）并存：前者减少重复 LLM，本项减少重复 `get_table_info`/格式化。

## 4. 环境变量与参数速查

| 名称 | 说明 |
|------|------|
| `MODIFY_ORIGINAL_DATA_ORM_FIRST` | 非 `0/false/off` 时 ORM 优先读行 |
| `MODIFY_LOOKUP_ORM_FIRST` | 非 `0` 时自然语言定位先 ORM |
| `MODIFY_SANDBOX_DIRECT_SQL` | 沙箱直拼 UPDATE，避免 Text2SQL 生成 |
| `MODIFY_SANDBOX_PREVIEW_MODE` | 沙箱预览模式：`subset`（默认子集库写验证）、`full_copy`（整库副本+写验证）、`skip_update`（跳过写验证，仅 diff 预览） |
| `MODIFY_BATCH_PREVIEW_STREAM` | 批量预览是否逐条推流（默认开） |
| `MODIFY_ALLOW_FAST_APPLY` | 允许 `skip_preview` + 白名单字段时直落库 |
| `TEXT2SQL_SQL_CACHE_TTL` / `TEXT2SQL_SQL_CACHE_MAX` | SQL 生成结果缓存 |
| `REACT_OBSERVE_FAST_STUB` | modify 预览后跳过 observe LLM |
| `SANDBOX_DB_COPY_DIR` | SQLite 沙箱副本**父目录**；未设时默认为系统 `TEMP` 下 `badcase_sandbox_db_copy`（见 `sandbox_executor.default_sandbox_db_copy_dir`） |
| `PERF_LOG=1` | 打印 `[PERF][sandbox] db_copy_ms=...`、批量 `[PERF][modify_sandbox] ...`，便于确认拷贝占比 |

**工具参数：**

- `target_ids` + `batch_items`：批量预览/落库。
- `skip_preview: true`：在 `MODIFY_ALLOW_FAST_APPLY=1` 且字段白名单内时跳过沙箱。

---

## 5. SSE 与前端约定

- **`batch_preview_row`**：`row` 内含 `index`、`total`、`target_id`、`plan_id`、`record_title`、`diff`、`before`、`after` 等；`reactEngineLegacyStream.js` 写入 `step.batchPreviewRows` 并追加步骤日志行。
- 未单独映射的引擎事件仍可经 v1 **`stream` / `lane=engine`** 整包下发；`batch_preview_row` 已在 `sse_react_v1` 中标注 phase，便于埋点。

---

## 6. 与「批量落库」对称性（已实现口径）

| 环节 | 预览路径 | 落库路径 |
|------|----------|----------|
| 读行 | 批量 IN ORM | 落库不依赖读行 |
| 写沙箱/提交 | 一次副本 + 多语句 / 或单条 | `_apply_modifications_batch` |

---

## 7. 后续可做（未强制实现）

- **分段耗时结构化**：`init_ms` / `orm_fetch_ms` / `sandbox_ms` 写入 observation 或日志 JSON。
- **快速模式 UI**：显式「跳过预览一键应用」勾选，对应下发 `skip_preview`（需服务端开 `MODIFY_ALLOW_FAST_APPLY`）。
- **回滚策略**：若产品要求「可撤销」，需独立事务/审计表，与当前「直写库」设计不同，需单独需求。
