# 需求文档 - 界面语言与用户偏好设置

## 1. 概述

### 1.1 背景

BadCase Doctor 客户端（Electron + Vue 3）当前界面文案以简体中文为主。为满足不同用户习惯与后续国际化，需要提供**界面语言**能力；首批支持 **简体中文** 与 **English**。

用户习惯在**全局、易发现**的位置管理个人偏好。现有主工作区顶部栏右侧已有**用户头像**及下拉菜单（`ProjectWorkspaceShell`：`user-dropdown` / `user-avatar`），适合作为**偏好设置的统一入口**，避免在多处散落配置。

### 1.2 目标

1. **语言切换**：用户可在界面内选择「简体中文 / English」，切换后**即时或短刷新**生效，覆盖主界面可见文案（按钮、标签、占位符、菜单项等）。
2. **入口位置**：在用户头像展开的下拉菜单中增加**「偏好设置」**（或「设置」）项；点击后打开**设置面板/弹窗**，其中**首项为语言**，并为后续更多配置预留结构。
3. **可扩展**：同一套「偏好设置」承载未来项（如主题、通知、编辑器字号等），本需求只规定**语言**与**入口/信息架构**，不一次性实现全部未来项。

## 2. 参考：现有 UI 位置

| 元素 | 说明 |
|------|------|
| 顶部栏右侧 | 布局切换按钮旁为 `user-dropdown` |
| 头像 | `user-avatar`（当前为占位图标），点击展开 `user-menu` |
| 现有菜单项 | 通知、帮助、团队管理、个人资料、退出登录等 |

本需求在**不弱化现有账号相关操作**的前提下，在菜单中增加「偏好设置」；语言选择在**偏好设置界面**内完成，避免在头像旁堆叠过多一级控件。

## 3. 功能需求

### 3.1 语言范围（MVP）

| 语言代码（建议） | 展示名称（界面内） | 说明 |
|------------------|-------------------|------|
| `zh-CN` | 简体中文 | 默认语言（可与浏览器/Electron 系统语言联动，见 3.3） |
| `en` | English | 英文界面 |

后续若增加语言，在同一列表中扩展即可。

### 3.2 偏好设置入口

- **位置**：用户头像下拉菜单（`user-menu`）中，建议在「个人资料」附近或「退出登录」上方增加一条：**偏好设置**（英文界面下：`Preferences` 或 `Settings`）。
- **行为**：点击后关闭下拉菜单，打开**偏好设置**界面（推荐：**居中模态框**或**右侧抽屉**，与现有「个人资料」等弹层风格一致）。
- **偏好设置界面结构（MVP）**：
  - **区块一：语言 / Language**
    - 单选：`简体中文` / `English`（或下拉选择，二选一即可）。
    - 变更后立即保存并应用（见 3.4）。
  - **预留**：可增加「关于本页」说明：「更多显示与行为选项将陆续提供。」（文案需随当前语言切换。）

### 3.3 默认语言策略

- **首次安装 / 无本地记录时**：优先读取 **Electron `app.getLocale()`** 或 **浏览器 `navigator.language`**；若以 `en` 开头则默认 English，否则默认 `zh-CN`（可配置映射表）。
- **用户显式选择后**：以用户选择为准，**持久化**到本地（见 4.1），下次启动不再覆盖。

### 3.4 生效范围与体验

- **范围**：Electron 主窗口内 Vue 应用所控制的 UI 文案（顶部栏、侧边栏、对话面板、表格列头、按钮、提示等）。**不要求**本迭代翻译后端返回的业务错误信息（可后续单独约定）。
- **体验**：
  - 切换语言后，当前页应立即反映新语言；若个别深层组件需整页刷新才可统一，可接受**一次轻量刷新**，但需在文档/实现中说明。
- **日期与时间**：`toLocaleString` 等可与语言联动（`zh-CN` / `en`），避免中英文混排混乱。

## 4. 技术方案要点（供实现参考）

### 4.1 持久化

- 使用 **localStorage**（或 Electron `userData` 下配置文件，二选一以项目现有习惯为准）存储键如：`app.locale` = `zh-CN` | `en`。
- 应用启动时读取并初始化 i18n。

### 4.2 前端国际化实现

- 推荐引入 **vue-i18n**（或项目已选方案），文案以 **key + 各语言 JSON/TS 资源** 维护。
- 将现有硬编码中文逐步迁入语言包；MVP 可先覆盖**主框架与高频路径**（顶部栏、用户菜单、偏好设置弹窗），其余页面迭代补齐。

### 4.3 组件改动面

- **`ProjectWorkspaceShell.vue`**：用户菜单新增「偏好设置」菜单项及对应 `emit`；壳层可接收 `locale` 或由全局 i18n 自动切换。
- **新建**：`PreferencesModal.vue`（或等价）—— 语言选择 UI。
- **父级**（如 `ProjectDetail.vue`）：处理打开/关闭偏好设置、与全局 locale 同步（若状态提升需要）。

### 4.4 与「更多配置」的关系

- 偏好设置弹窗采用**左侧导航 + 右侧内容**或**单页分区**均可；MVP 仅「语言」一个分区，**导航可隐藏或仅一项**，避免过度设计。
- 后续新增「外观」「通知」等时，在同一弹窗内加导航项即可，无需再增加新的顶层入口。

## 5. 非功能需求

| 项目 | 要求 |
|------|------|
| 可维护性 | 文案集中管理，禁止在模板中散落双语 `if/else` |
| 一致性 | 中英文下布局不错位、按钮不被截断 |
| 可测试性 | 切换语言后关键路由/组件可做一次冒烟（手动或 E2E） |

---

## 6. 验收标准（MVP）

1. 用户通过**头像 → 偏好设置**可打开设置界面。
2. 可在 **简体中文 / English** 间切换，界面主文案随之切换。
3. 刷新应用或重新打开后，**仍保持**上次选择的语言。
4. 偏好设置 UI 结构支持后续增加配置项，无需推翻重做。
