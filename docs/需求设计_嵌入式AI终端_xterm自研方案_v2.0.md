## 0. 修订说明（为何推翻「底部终端里聊 AI」）

**错误做法（已废弃）**：在底部嵌入式终端区域下方再放一块「自然语言输入框 + 生成命令」，把 AI 对话塞进终端黑框周边。这会导致：

- 视觉割裂：大块黑底终端 + 突兀白底表单，不像专业 IDE；
- 职责混乱：终端是 **PTY 执行与回显面**，不是 **对话与意图编排面**；
- 与行业标杆不一致：Cursor 等产品的 **自然语言、生成 bash/python 一行命令、策略选择** 均在 **对话面板（Chat / Composer）** 内完成。

**正确做法（本文档从本节起一律按此执行）**：

| 区域 | 职责 | 禁止 |
|------|------|------|
| **右侧对话面板**（现有 SimpleChatPanel / AI 助手） | 用户用自然语言描述意图；AI 在 **对话流** 中输出说明、结构化结果，以及 **可执行的命令块**（bash / PowerShell / `python -c` 等） | 不把「主 AI 输入」放在底部终端下方 |
| **底部嵌入式终端**（xterm + PTY/SSH） | 真实 Shell 会话：展示输出、接收键盘输入、承接从对话 **投递** 过来的命令并执行 | 不把对话面板里的长文讨论、表格统计主 UI 塞终端 |

**体验对标**：以 Cursor 为参考（产品内截图与公开交互一致），包括但不限于：

- 对话里出现 **带标题的「终端意图」块**（例如统计代码行、跑诊断脚本），块内是 **可执行命令或脚本**；
- 块 **顶部工具条**：标题摘要、**复制**、**跳转到终端/执行**（箭头类按钮）、**更多（⋯）**；
- **⋯ 展开**：与执行策略相关的选项（见 §4.4），而非空菜单。  
- 对话内可执行块可采用 Cursor **行内执行卡**样式：标题行 + `$` 命令区 + 底栏 **Skip / Allowlist / Run**（见 **§4.1.1**）。

## 1. 背景与目标

### 1.1 背景

测试与开发排查需要：在单窗口内完成「想清楚 → 生成命令 → 在真实环境执行 → 回看输出 → 再追问 AI」。Cursor 将 **对话生成命令** 与 **底部终端执行** 分离又打通；BadCase Doctor 需在 Web 内嵌实现同类闭环，且终端必须内嵌（非独立桌面终端应用）。

### 1.2 总目标

1. **对话驱动**：用户在 **右侧 AI 对话面板** 中描述意图，AI 可生成 **bash / PowerShell / 单行 python -c** 等可执行内容。  
2. **一键落地**：对话中的命令块提供 **复制**、**发送到嵌入式终端执行**（或先聚焦底部终端再粘贴），用户无需在终端里重新打字。  
3. **底部终端专职执行**：多 Tab、本地/SSH、流式输出、审计等与执行相关能力仍由底部终端承担。  
4. **策略可控**：通过 **⋯ 菜单** 配置「每次询问 / 白名单自动 / 等」类执行策略（实现阶段可分步，见 §6）。

## 2. 信息架构与数据流

```text
┌─────────────────────────────────────────────────────────────┐
│  项目详情主区（列表 / 详情编辑）                               │
├──────────────────────────────┬──────────────────────────────┤
│                              │  右侧：AI 对话面板             │
│                              │  - 自然语言                    │
│                              │  - 回复中的「命令块」          │
│                              │    [ 标题 | 复制 | →终端 | ⋯ ] │
│                              │    ┌──────────────────────┐   │
│                              │    │ $ python -c "..."   │   │
│                              │    └──────────────────────┘   │
├──────────────────────────────┴──────────────────────────────┤
│  底部：嵌入式终端区（对标 Cursor 底部 Terminal）                │
│  ┌────────────────────────────┬──────────────────────────────┐ │
│  │ 左侧主区：xterm 流式输出    │ 右侧：**竖向会话列表**        │ │
│  │ 须同时可见「输入的命令行」  │ 区分：本地 Shell / SSH /      │ │
│  │ + 命令执行后的完整回显      │ **Agent 终端**（对话投递）等   │ │
│  └────────────────────────────┴──────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

**关键数据流**：

1. 用户在对话题框输入 → LLM 流式回复 → 解析或组件渲染出 **命令块**（含元数据：建议标题、shell 类型、是否多行）。  
2. 用户点击 **复制** → 剪贴板。  
3. 用户点击 **→ 终端**（名称可本地化：「在终端中运行」「跳到终端」）→ 前端将命令写入 **目标会话**（见 §4.3）的 PTY 输入并发送执行，并 **自动展开/聚焦底部终端面板**。  
4. **跳转后的可见性（强制）**：用户在该 xterm 主区内必须能连续看到 **（a）被投递的命令行** 与 **（b）该命令产生 stdout/stderr 直至结束**（与 Cursor 一致：不是跳到一个空黑框或看不到刚才那条命令）。若采用「仅注入不显示回显」的实现，则 **不合格**。  
5. **⋯** → 展开执行策略子菜单（§4.4）。

## 3. 功能需求

### 3.1 对话面板侧（优先实现）

| 编号 | 功能 | 说明 |
|------|------|------|
| C-1 | 命令块展示 | AI 回复中的可执行片段以 **独立卡片** 展示（**禁止** 与普通 Markdown 代码块无差别）；深色底、圆角、等宽字体、顶部工具条；可选 **§4.1.1** 行内执行卡（Skip / Allowlist / Run）；细则见 **§4.1**。 |
| C-2 | 标题行 | 卡片顶部一行 **意图摘要**（如 `Recount LOC in workspace for selected extensions`），左侧可配小图标。 |
| C-3 | 复制 | 一键复制 **完整可执行文本**（含 `python -c` 整段等）。 |
| C-4 | 跳转终端 / 执行 | 按钮将命令 **投递到底部嵌入式终端** 的 **指定会话**（默认：新建或复用「Agent」类会话，见 T-5），并触发 **底部面板可见 + 焦点**。跳转后用户须在主区看到 **命令 + 回显**（§4.3）。若终端未连接，应先提示或排队至连接成功（产品规则另定）。 |
| C-5 | ⋯ 更多选项 | 展开菜单，至少预留与 Cursor 同类的 **执行策略** 项（见 §4.4）；第一期可实现子集 + 占位。 |
| C-6 | 与项目上下文 | 可选：`@` 工作区、当前文件路径等（与现有 Chat 能力对齐，不重复造轮子）。 |

### 3.2 底部终端侧（与 v2.0 一致部分保留）

| 编号 | 功能 | 说明 |
|------|------|------|
| T-1 | xterm 渲染、多 Tab、本地 PTY / SSH | 不变。 |
| T-2 | 不接受「主 AI 自然语言输入框」 | 终端区 **不出现** 大段对话输入；仅保留与执行直接相关的极简控件（如会话列表、清屏、连接配置）。 |
| T-3 | 承接投递 | 必须实现稳定 API：`injectCommand(text, sessionId?)` 或由父级 `provide`；投递后 **同一 xterm 缓冲区** 内须能看到键入/注入的命令行及后续输出。 |
| T-4 | 审计 / 高危确认 / 白名单 | 仍以服务端与配置为准；可与对话块「执行」联动做二次确认。 |
| T-5 | **右侧会话栏（Cursor 级）** | 细则见 **§4.3**（含与顶部 Tab 关系、三类会话、跳转高亮、只读可选）。 |

### 3.3 与业务联动

- 测试用例失败「打开诊断」：优先 **打开底部终端** 并（可选）向 **对话面板预置一条用户消息** 模板，而不是只在终端底下塞一行小字。  
- 终端输出 → BadCase：仍在对话或独立动作中完成，**不在终端底栏堆叠大段 UI**。

## 4. 交互与视觉（Cursor 级）

### 4.1 对话内命令块（对标 Cursor；**必须与普通 Markdown 代码块明确区分**）

可执行命令 **不得** 仅渲染为聊天里的普通 \`\`\` 代码围栏（无操作条、与说明性代码混同）。须采用 **独立卡片组件**，至少满足：

| 要素 | 要求 |
|------|------|
| 容器 | 深色底、圆角（约 6～8px）、与主对话背景有 **层级差**（边框或背景对比），一眼可辨「可执行块」。 |
| 顶部工具条 | **标题摘要**（如「统计代码行数」、与对话中意图一致，可截断 + 全文 tooltip）；**复制**；**跳转终端**（箭头图标）；**⋯**（执行策略菜单）。 |
| 代码区 | 等宽字体；`$` 或与 Shell 一致的提示符可选；长行默认换行或横向滚动（产品二选一定稿）。 |
| ⋯ 菜单 | 第一期至少包含 **「每次执行前询问」**、**「自动运行（受白名单约束）」** 等项的 **可点或占位**（灰显 +「后续版本」亦可，但不得空菜单），见 §4.4。 |

#### 4.1.1 行内「执行 bash / PowerShell / 单行脚本」卡片样式（对标 Cursor 截图）

除上表通用工具条外，允许采用与 Cursor **同构** 的 **整卡布局**（产品可选用 **4.1 顶栏四键** 与本节 **底栏 Run 条** 二选一或组合，但 **须与普通 Markdown 代码块明显不同**）：

| 区域 | 样式与行为 |
|------|------------|
| **卡片容器** | 深灰底、略浅于聊天背景；**细浅色描边**；**圆角**（约 6～8px）；内边距充足，标题 / 命令 / 底栏分区清晰。 |
| **块上方（可选）** | 与 Cursor 一致可存在 **可折叠推理条**（如「Thought for 1s」），与 ReAct/思考阶段对齐；**不**替代命令块本身。 |
| **标题区** | 卡片 **顶部** 一行 **浅灰文案**，概括本块意图（例：`Verify react_simplified.py syntax Set-Location, python`）；可截断，hover **tooltip** 展示全文。 |
| **命令区** | 以 **`$`** 或当前 Shell 提示风格起行；**等宽字体**；支持 **简易语法高亮**（关键字、路径字符串等与说明性代码块区分）。命令可为 **bash**、**PowerShell**（如 `Set-Location "..."; python -m py_compile ...`）、或 **单行 `python -c`** 等。 |
| **底栏左侧** | **Skip** 文案 + 快捷键提示（如 **Esc**），表示跳过本块、不执行（与 Cursor 一致）。 |
| **底栏右侧** | **Allowlist** 类按钮：深灰圆角，文案示例 `Allowlist 'Set-Location' + 1`，表示将本命令中某可执行名纳入白名单（与 §4.4、服务端白名单联动）。 |
| **底栏主操作** | **Run** 按钮：**主色（如蓝）**、圆角，可带 **回车键图标**；语义为 **在约定环境执行本块命令**（默认等价于 **跳转底部终端并注入**，见 §4.2 / §4.5）。 |

**说明**：**复制**、**跳转终端（箭头）**、**⋯** 可与上述 **Run 条** 并存（例如顶栏保留复制/⋯，底栏专注 Run / Skip / Allowlist），避免重复按键则需在 UI 稿中统一。

**区分度自检**：若用户无法在不读正文的情况下，仅凭样式判断「这一块可以一键下发终端」，则 **不合格**。

### 4.2 「箭头 / 跳转终端」行为定义

- **最小可用（MVP）**：将命令字符串写入目标 PTY 并发送换行；**滚动底部终端面板进入视口**；**同一视窗内** 用户能看到命令出现在终端里并 **接着看到该命令的输出**（光标跟随滚动到底部更佳）。  
- **增强**：若命令需用户审阅，可先仅粘贴不发送，由设置项控制（与 §4.4 联动）；**注意**：若产品开启「仅粘贴不发送」，仍须在用户确认发送后满足 §4.5，**不得**长期停留在「无回显的空会话」而不提示。

### 4.3 底部终端布局：主区 + 右侧会话栏（对标 Cursor 截图）

**问题背景**：仅「跳到终端」但主区不展示 **已执行命令 + 结果**，或无法在右侧区分 **本次对话命令对应的会话**，会与 Cursor 体验不一致。

#### 4.3.1 结构关系（与现有顶部 Tab）

- 底部终端区 **必须** 包含 **竖向会话列表（右侧窄栏）**。  
- 与 **现有顶部横向 Tab** 允许 **共存**（上下/内外分工）或 **合并为单一会话切换控件**（产品定稿二选一并需在 UI 稿中固定），但无论哪种方案，用户必须能 **区分并切换** 多个会话，且 **右侧竖栏为对标 Cursor 的必选信息架构**（窄栏列表 + 主区 xterm）。

#### 4.3.2 会话类型与标识

每个会话项须 **显式区分** 类型（图标 + 文案或仅图标 + tooltip）：

| 类型 | 说明 |
|------|------|
| **本地 Shell** | 本机 PTY，如 PowerShell / bash。 |
| **SSH** | 远程会话，可带主机名截断。 |
| **Agent 会话** | 由 **对话面板「跳转终端」** 投递命令而创建或承接的会话；与纯手打本地会话 **视觉不同**。 |

**创建与驱动规则（必须写死口径）**：

- **用户手动只能“新建终端”**：新建得到的会话类型只能是 **本地 Shell / SSH**（用户手动驱动，键盘输入为主）。
- **Agent 会话不能由用户手动新建**：只能由 **右侧对话面板** 的执行链路（如「跳转终端/运行」）自动创建/复用并驱动。
- **UI 区分点在右侧会话栏**：是否为 Agent 会话，体现在 **右侧竖向会话列表** 的类型标识与选中高亮上，而不是“新建”菜单里提供一个「新建 Agent 终端」入口。

#### 4.3.3 从对话「跳转终端」时的联动（强制）

1. **自动选中**：投递前自动 **选中** 对应的 **Agent 会话**（**新建** 或按规则 **复用** 已有 Agent 会话，规则产品定稿）。  
2. **右侧高亮**：右侧会话列表中 **当前项高亮**，与主区 xterm 内容一致。  
3. **主区内容**：该会话的 xterm 缓冲区须 **完整显示** 被注入的 **命令行** 以及 **随后 stdout/stderr（直至该命令结束）**，见 §4.5。

#### 4.3.4 可选：Agent 会话只读

- 可将 Agent 会话设为 **只读**（用户键盘无法输入，仅允许从对话块注入）。  
- 底部终端区可增加 **提示文案**（与 Cursor「Agent terminals are read-only」同类），避免用户误以为键盘失效是 Bug。

### 4.4 ⋯ 菜单（与第三张参考图对齐，可分阶段实现）

下列为 **目标全集**，开发可分 P0 / P1：

| 选项（示例文案） | 含义 |
|------------------|------|
| 每次执行前询问 | 从对话块点「运行」时先弹确认（默认安全）。 |
| 自动运行（受白名单约束） | 仅当命令匹配服务端/客户端白名单时自动注入执行。 |
| 使用白名单 | 展示或编辑与当前会话相关的允许前缀/命令（与配置中心联动）。 |
| 允许运行任意命令 | 高危，需强确认 + 审计。 |
| 允许「python」等语言/工具 | 细粒度白名单条目（与 Cursor「Allowlist 'python'」同类）。 |

**说明**：不要求第一期实现全部逻辑，但 **文档与 UI 占位** 需按上表设计，避免再次做成「无菜单或空菜单」。

### 4.5 命令投递可见性（强制，与验收挂钩）

点击命令块 **「跳转终端」** 后，须同时满足：

1. **底部终端面板自动展开**（若已折叠）并 **获得合理焦点**（主区或终端容器可聚焦，便于键盘滚动）。  
2. **主 xterm 区** 在同一 PTY 流中 **可见**：  
   - **被注入的完整命令行**（与用户将要执行的字符串一致，含多行/引号）；  
   - **该命令执行产生的 stdout/stderr**，直至进程结束或会话可区分的结束态。  

**明确判定为不合格的实现**：

- 「仅粘贴到剪贴板 / 输入框但不发送」且用户未再操作却宣称已执行；  
- 跳转到 **无输出、非目标会话** 的空白 xterm，且未提示连接失败或会话错误；  
- 命令在后端执行但前端 **不展示** 注入行与流式回显（与用户可见终端真相不一致）。

### 4.6 底部终端区域禁止项

底部终端区内 **只允许**：

- 终端主显示区（xterm）、**右侧竖向会话栏**、与执行直接相关的控件：**清屏**、**连接/模式（本地·SSH）**、**新建/关闭会话**、**输出缓冲（若有）**、审计导出入口（若保留）等。

**禁止**：

- 任何形式的 **AI 自然语言大输入框**（主对话输入）、**在终端底部再嵌一套 Chat**；  
- 将「生成命令、讨论执行策略」放在底部终端区（此类 **一律在右侧 AI 对话面板** 完成，见 §0）。

## 5. 技术方案（与实现约束）

### 5.1 前后端分工

- **对话面板**：沿用现有流式 Chat；新增消息类型 `terminal_command_block`（或 Markdown 约定 + 解析），包含：`title`、`shell`、`content`、`id`。  
- **终端**：继续 Socket.IO + xterm；父组件 **inject** 投递方法供 Chat 子树调用（或全局事件总线，二选一需统一）。  
- **AI 生成命令**：可复用现有 `/api/terminal/ai_suggest` 作为 **工具能力**，但 **入口必须在对话流**，不在终端底栏。

### 5.2 安全

- 对话块「一键执行」与手动键入等价对待：**审计、高危正则、白名单** 均适用。  
- ⋯ 中的「自动运行」必须 **默认关闭**，且与后端策略一致。

## 7. 验收标准（修订）

### 7.1 会话栏与投递联动（对标 Cursor）

- [ ] 底部终端区存在 **右侧竖向会话列表**（窄栏）；与 **顶部横向 Tab** 可 **共存或合并** 为一种会话切换方案，但 **竖栏为必选**。  
- [ ] 每个会话项可区分 **本地 Shell / SSH / Agent** 三类（图标或标签）。  
- [ ] 从对话 **「跳转终端」** 时：自动 **选中** 对应 **Agent 会话**（新建或复用），右侧列表 **高亮该项**；主 xterm 区 **连续显示** **命令行 + 后续 stdout/stderr（至结束）**。  
- [ ] （可选验收）Agent 会话支持 **只读** 时：键盘无法输入，底部有 **只读提示** 文案。

### 7.2 命令块 UI 与 ⋯ 菜单

- [ ] 可执行命令为 **独立卡片**，**不得** 与普通 Markdown 代码块在样式上无法区分；卡片含 **标题摘要、复制、跳转终端（箭头）、⋯**（或 **§4.1.1** 与顶栏组合）。  
- [ ] **⋯** 菜单至少包含 **「每次执行前询问」**、**「自动运行（受白名单约束）」** 等项（可部分为占位，但菜单非空）。  
- [ ] 交互与布局 **与 Cursor 截图一致**（标题条 + 代码区 + 操作区层级）。  
- [ ] 支持 **§4.1.1** 所述 **行内执行卡**变体：深灰描边圆角容器、顶部意图标题、**`$` + 等宽命令 + 语法高亮**、底栏 **Skip（Esc）**、**Allowlist …**、**Run（主按钮）**；**Run** 与「跳转终端并执行」语义一致并满足 §4.5。

### 7.3 命令投递可见性（强制）

- [ ] 点击「跳转终端」后底部终端 **自动展开/聚焦**。  
- [ ] 主 xterm 区可见 **被注入的完整命令行** 及 **该命令的完整终端输出**；**不合格**：仅粘贴不发送、或跳到无输出的空会话且无错误提示。

### 7.4 禁止项与基础能力

- [ ] 底部终端区 **无任何 AI 对话输入框**；自然语言交互 **仅在右侧 AI 对话面板**。  
- [ ] 嵌入式终端仍支持本地 Shell、SSH、多会话、审计等基础能力（不因改版删除）。  
- [ ] 用户 **仅在右侧对话面板** 进行与「生成/讨论可执行命令」相关的自然语言交互（与 §4.6 一致）。
