# 需求文档：门控与 THINK 流式「真·预热」及可取消设计（复盘用）

**版本**：2026-03-29  
**状态**：设计稿 / 未实现  
**目的**：在已落地的「门控与 gather 并行」「门控等待期拼 think_prompt + preloop」之上，论证是否进一步做到 **门控未结束即启动 THINK 流式 LLM**，并定义 **纯对话短路时的取消与计费边界**，便于评审与事后分析。

---

## 1. 背景与问题

### 1.1 已落地能力（本文不重复实现）

| 能力 | 说明 |
|------|------|
| 门控 LLM 与 gather 并行 | `REACT_TOOLS_INTENT_ENABLED=1` 且需调门控模型时，与「项目/计划名 + format_tools」并行。 |
| 门控期 preloop | 进入门控分支即启动 `_prefer_modify_over_create` 与 `match_skill`；纯对话路径 `cancel`。 |
| 门控期 think_prompt 预热 | `REACT_TOOLS_INTENT_THINK_WARM=1`（默认）且门控 task 未完成时，`to_thread` 构建首轮 THINK 的 `prompt`；纯对话路径 `cancel`。 |

### 1.2 仍未覆盖的延迟

首轮 **THINK 流式请求**（`_resolve_chat_stream_iter*` → 子线程读队列）仅在确认 `need_tools=True` 之后才启动。若门控 LLM 耗时 \(T_g\)，拼 prompt 耗时 \(T_p\)（已可与 \(T_g\) 重叠），则 **首 token 仍至少受「门控尾部」约束**，无法与 \(T_g\) 完全重叠。

### 1.3 产品诉求（假设）

- 在 **误判成本可接受** 的前提下，进一步压缩「用户发送 → 首轮规划流第一个可见增量」的墙钟时间。  
- 当门控最终判定 **纯对话** 时，应 **尽快停止** 已发起的 THINK 流，并明确 **是否计费 / 如何观测浪费**。

---

## 2. 目标与非目标

### 2.1 目标

1. **可选**开启「门控与 THINK 流式并行」：在 `need_tools` 尚未确定时，即可向模型发起流式请求并缓冲 chunk。  
2. 门控结果为 **纯对话** 时：  
   - 停止向客户端继续下发 THINK 相关 SSE（若已下发需定义收敛策略）；  
   - 底层 HTTP/SDK 流在能力范围内 **abort** 或 **尽快关闭**；  
   - 文档化 **无法 100% 取消** 的场景（供应商已计费首包等）。  
3. 门控结果为 **需工具** 时：消费已缓冲的流或无缝续接，**不重复**整段生成（或重复策略可配置）。  
4. 提供 **开关 + 指标**，支持 A/B 与复盘。

### 2.2 非目标

- 不强制改变默认产品策略（可与现网「门控默认关/开」独立配置）。  
- 不承诺所有云厂商 API 均支持零成本取消。  
- 不在本文档中规定具体模型名与单价。

---

## 3. 方案概览

### 3.1 状态机（逻辑）

```
[Gather 完成 + result_context 就绪]
    → 若开启「流式预热」且门控需等待：
         并行：GateTask || ThinkStreamTask（读流到内存队列，默认不向 SSE 吐 THINK 正文）
    → Gate 完成：
         need_tools=False → Cancel ThinkStreamTask，清空队列，走 summary_stream 短回复
         need_tools=True  → 将队列中已读 chunk 按序喂给现有 SSE 循环（或切换为「同连接续读」）
```

### 3.2 关键设计抉择

| 抉择点 | 选项 A | 选项 B | 建议倾向 |
|--------|--------|--------|----------|
| 预热期是否向前端推 THINK | 不推（仅缓冲） | 推「占位/灰显」 | **A**：避免纯对话闪一下规划流 |
| 与现有子线程+`queue` 模型 | 复用同一 worker，加「许可闸」 | 独立连接，结束后二选一 | 需评估 LLM 客户端是否支持 **单连接中途 abort** |
| 重复生成 | 禁止：必须续用缓冲 | 允许：discard 后重拉 | **禁止**更省成本，实现更难 |

---

## 4. 竞态与取消语义

### 4.1 时序竞态

1. **Gate 先完成（纯对话）**  
   - Think 线程可能尚未首 token，或已产生部分 chunk。  
   - 要求：`ThinkStreamTask` 监听 `asyncio.Event` / `threading.Event`，置位后 **退出迭代** 并 `queue` 投 `DONE` 或 `CANCELLED`。

2. **Think 先产出 chunk**  
   - Gate 尚未返回。  
   - 若采用 **缓冲不推 SSE**：前端无感知；Gate 为纯对话时丢弃缓冲。  
   - 若已误推 SSE：需补 **回滚协议**（前端忽略某 `seq` 区间或收到 `stream_reset`），复杂度高，首版不建议。

3. **Gate 超时**  
   - 现网策略：超时 → 保守 `need_tools=True`。  
   - 流式预热下：超时后应 **继续** THINK，与今日行为一致；无需 cancel。

### 4.2 底层取消

- 若 `dashscope` / OpenAI 兼容客户端 **支持** `close()`、`aclose()` 或 `response.close()`：在 `Event` 置位时调用，并记录 `PERF`/`cancel_reason`。  
- 若 **不支持**：仅停止本地 `for chunk in stream` 循环，**可能仍计首 token** —— 必须在文档与开关说明中写明。

---

## 5. 观测与复盘指标

建议在 `PERF_LOG=1` 或独立 `REACT_STREAM_WARM_METRICS=1` 下记录（字段名可再定）：

| 字段 | 含义 |
|------|------|
| `gate_wait_ms` | gather 结束 → gate 返回 |
| `think_stream_start_ms` | 相对请求起点，首次调用流式 API 的时间 |
| `think_first_chunk_ms` | 首 chunk 到达本地的时间 |
| `think_stream_cancelled` | 是否因纯对话被取消 |
| `think_chunks_buffered` | 取消前已缓冲条数 / 字符数 |
| `think_stream_overlap_ms` | `think_first_chunk_ms` 与 `gate_wait_ms` 的 overlap 估算 |

用于复盘：**省下的墙钟** vs **多消耗的 token 比例**。

---

## 6. 配置建议（草案）

| 环境变量 | 含义 | 默认建议 |
|----------|------|----------|
| `REACT_TOOLS_INTENT_STREAM_WARM` | 是否允许门控等待期启动 THINK 流 | `0`（关，直到客户端验证 abort） |
| `REACT_TOOLS_INTENT_STREAM_WARM_MIN_GATE_MS` | 仅当门控预计 > 该毫秒才预热（可选启发） | 未定时可不设 |
| `REACT_TOOLS_INTENT_STREAM_WARM_EMIT` | 预热期是否向 SSE 发 THINK | `0` |

与现有 `REACT_TOOLS_INTENT_THINK_WARM`（仅拼 prompt）**独立**，避免混淆。

---

## 7. 前端影响（若预热期不发 SSE）

- **无协议变更**；与当前一致。  
- 若未来支持「预热期灰显」：需补 `phase_wait` 或 `stream` 子类型约定，另起小节。

---

## 8. 风险清单

| 风险 | 缓解 |
|------|------|
| 纯对话多烧 token | 默认关闭；仅对高价值会话开启；指标监控 |
| 双请求/双连接 | 严格单 worker + cancel；集成测试 |
| 供应商 SDK 不释放连接 | 超时与连接池监控；厂商工单 |
| 与增量总结/其它队列线程混淆 | THINK 队列独立命名、独立 cancel 事件 |

---

## 9. 实现阶段建议

1. **Phase 0**：在测试环境对当前 LLM 客户端做 **abort 可行性探测**（最小脚本：开流 → 0.5s 后 close → 看服务端与账单行为）。  
2. **Phase 1**：缓冲不推 SSE + cancel + 指标，默认关。  
3. **Phase 2**：默认开（若 Phase 0 证明 abort 有效且成本可接受）。  
4. **Phase 3**（可选）：启发式「仅慢门控才预热」。
